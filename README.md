# Halyk Career Quest — AI-платформа карьерных траекторий и развития компетенций

**Хакатон HackAlem AI 2026** · Трек **Halyk Bank** · Кейс **Career Quest**

---

## 1. Описание проблемы и целевая аудитория

В крупном банковском финтехе классические подходы к развитию персонала часто страдают от двух крайностей:
1. **Ручные планы развития (ИПР)** требуют колоссальных трудозатрат HR и тимлидов, быстро устаревают и не учитывают реальную динамику закрытия задач.
2. **Наивные алгоритмические рекомендательные системы** работают по однофакторному правилу («у сотрудника самый низкий балл по навыку X — назначим ему тренинг по X»). 

### Почему наивное решение ломается на практике:
Если у Middle Backend-разработчика ниже всего оценка по навыку *Public Speaking (ур. 0)*, но сотрудник уже трижды отказывался или не являлся на подобные митапы, а для перехода на целевой грейд Senior критически необходим *System Design (ур. 2 из 4)*, наивная система порекомендует бесполезный для банка и нежелательный для сотрудника тренинг по публичным выступлениям.

**Целевая аудитория:**
- **Сотрудники (инженеры, аналитики, продакт-менеджеры):** получают прозрачную траекторию роста с объяснимыми рекомендациями следующих 1–3 шагов и мгновенным обновлением навыков при завершении программ.
- **HR-специалисты и руководители:** видят системный срез проседающих компетенций по банку, аналитику завершаемости развивающих форматов и список специалистов без активных рекомендаций.

## 2. Что реализовано

1. **Профиль сотрудника и матрица траектории:**
   - Отображение текущей роли, текущего грейда, стажа, руководителя и целевой роли/грейда (`career_goal`).
   - Детальная матрица разрывов компетенций (*Skill Gaps*) с визуальной 5-балльной шкалой, расчетом дефицита до требований целевого грейда и явным выделением критических навыков (*Critical Skills*).
   - **Интерактивные мини-спарклайны (Recharts) и Learning Velocity:** визуализация динамики изменения уровня компетенции во времени (Q3'25 – Сейчас) для каждого навыка, интерактивный тултип с историческими срезами и отметками пройденных программ, а также индикатор темпа освоения (уверенный рост, высокий темп, плато).
   - Расчет агрегированного процента готовности к промоушену.
2. **Многофакторный AI-слой рекомендаций (1–3 шага):**
   - Ранжирование программ развития на основе синергии минимум 3 факторов одновременно:
     1. **Требования целевого грейда/роли:** фокус на компетенциях, входящих в профиль целевой должности.
     2. **Критичность и разрыв навыка:** критические для роли компетенции имеют повышенный вес (множитель x3).
     3. **Поведенческая история сотрудника:** учет завершенных форматов (бонус) и штрафы за отказы (`declined`), неявки (`no_show`), брошенные курсы (`dropped`) и просрочки (`overdue`) по аналогичным типам активностей.
   - Фильтрация: исключение обязательных регуляторных курсов (`mandatory: true`), учет пререквизитов и запрет повторного прохождения уже завершенных событий (кроме повторяемого дискуссионного клуба `EV_036`).
3. **Объяснимое обоснование (Explainability):**
   - Текст рекомендации формируется детерминированно из реально рассчитанных факторов без «галлюцинаций» внешних LLM.
   - В UI выведен прозрачный разбор: весовой балл дефицита навыка, история активности и текстовое обоснование по всем 3 критериям.
4. **Интерактивное обновление прогресса:**
   - Кнопка «Отметить выполненным» на карточке рекомендации выполняет `POST /api/employees/:id/activities/:eventId/complete`.
   - Прогресс по развиваемым навыкам увеличивается на `gain` (не превышая `max_level`), в историю добавляется запись, пересчитываются процент готовности к грейду и пул рекомендаций в реальном времени.
5. **Экран HR-аналитики:**
   - Срез наиболее проседающих компетенций по всей организации (совокупный дефицит уровней, количество затронутых сотрудников, число критических разрывов).
   - Список сотрудников без рекомендованного следующего шага с указанием причины (100% готовность к промоушену, максимальный грейд Lead, дефицит пререквизитов).
   - Аналитика участия и конверсии в завершение по типам форматов (воркшопы, курсы, митапы, наставничество, сертификация) и топ популярных программ.
6. **Горячая догрузка данных без перезапуска (Панель жюри):**
   - Эндпоинт `POST /api/import` и форма в веб-интерфейсе для мгновенного мерджа проверочных профилей, событий и истории в формате схемы датасета.

## 3. Как работает основной сценарий: от входных данных до результата

```
[Данные: skills.json, employees.json, events.json, activity_history.csv]
                                │
                                ▼
         [Определение целевой роли и грейда (career_goal / next grade)]
                                │
                                ▼
         [Расчет разрывов: gap = max(0, required_level - current_level)]
                                │
                                ▼
          [Фильтрация событий: non-mandatory, не пройденные, пререквизиты]
                                │
                                ▼
    ┌─────────────────────────────────────────────────────────────┐
    │ Многофакторный скоринг:                                     │
    │ 1. Skill Score = useful_gain * 30 * (is_critical ? 3.0 : 1.0) │
    │ 2. History Delta = (completed * 6) - (negative * 14)        │
    │    (где negative: declined, no_show, dropped, overdue)      │
    │ 3. Specific Penalty = -25 (если отказывался от этого курса)  │
    │ Total Score = Skill Score + History Delta                    │
    └─────────────────────────────────────────────────────────────┘
                                │
                                ▼
                 [Сортировка -> Топ-3 рекомендации]
                                │
                                ▼
             [Сборка 3-факторного объяснения (Explainability)]
                                │
                                ▼
                 [Отображение в UI + Действие "Выполнить"]
```

## 4. Технологии и архитектура

- **Backend:** Node.js, Express, TypeScript (`tsx`). Данные хранятся в оперативной памяти процесса (`dataStore.ts`) с начальной инициализацией из каталога `/data`.
- **Frontend:** React 19, TypeScript, Vite, Tailwind CSS v4, Lucide Icons.
- **Интеграция:** Express монтирует Vite middleware в режиме разработки и раздает собранную статику в production.

### Диаграмма каталогов
```
/
├── data/                        # Стартовый датасет
```

## 5. Установка и запуск

### Требования
- Node.js 20+
- npm

### Шаги запуска:
```bash
# 1. Установка зависимостей
npm install

# 2. Запуск в режиме разработки (Backend API + Frontend на порту 3000)
npm run dev

# 3. Проверка типов и линтинг
npm run lint

# 4. Сборка для production
npm run build

# 5. Запуск собранного приложения
npm start
```
Приложение откроется на `http://localhost:3000`.

## 6. Пример проверки (Критерии 1–5 из ТЗ)

Для автоматического прогона всех 5 обязательных проверок выполните:
```bash
npx tsx src/scripts/verifyAllRequirements.ts
```

### Ручные шаги проверки:
1. **Поднятие сервиса:** `npm run dev` запускает Express и Vite на порту 3000 без ошибок. `npm run lint` проходит с 0 ошибок.
2. **Проверка ключевого кейса (Алексей Иванов, `EMP_001`):**
   - Откройте `EMP_001`.
   - Самый низкий навык в профиле — *Public Speaking* (ур. 0 из 2, разрыв 2).
   - В истории сотрудника зафиксировано **3 отказа/неявки** на софт-скилл митапы по ораторскому мастерству (`EV_006`).
   - Для перехода на Senior Backend критичны *System Design* (ур. 2 из 4, критичный разрыв 2) и *PostgreSQL*.
   - **Результат работы Career Quest:** на первом месте рекомендуется `EV_003` («Воркшоп: Архитектура распределенных систем и System Design») с наивысшим баллом (186 pt), а `EV_006` отсекается штрафами за историю.
   - Обоснование детально формулирует все 3 фактора.
3. **Отметка активности выполненной:**
   - Нажмите кнопку «Отметить выполненным» на карточке `EV_003`.
   - Уровень навыка *System Design* мгновенно вырастает с 2 до 3, *PostgreSQL* с 3 до 4.
   - Готовность сотрудника к грейду вырастает с 77% до 85%.
   - Рекомендации мгновенно пересчитываются (пройденный воркшоп исключается, первое место занимает архитектурный менторинг `EV_018`).
4. **Догрузка профилей жюри без перезапуска (`POST /api/import`):**
   - Перейдите на вкладку «Импорт (Жюри)».
   - Нажмите «Вставить тестовый кейс (EMP_JURY_99)» и «Импортировать в систему» (или отправьте `curl -X POST /api/import`).
   - Профиль мгновенно появляется в общем селекторе без перезапуска процесса, готовность и рекомендации рассчитываются на лету.
5. **HR-экран на полном датасете (200 сотрудников):**
   - Перейдите на вкладку «HR-Аналитика».
   - Отображаются ненулевые агрегаты: 200 сотрудников, топ проседающих компетенций по банку, аналитика вовлеченности по типам активностей и перечень сотрудников без рекомендаций с объяснением причин.

## 7. Используемые данные и внешние сервисы

- **Внешние AI API:** Не используются. Алгоритм рекомендаций и генерация объяснений полностью детерминированы, математически проверяемы и работают на 100% **офлайн**.
- **Данные:** Синтетический репрезентативный датасет в каталоге `/data`, смоделированный под структуру IT-блока Halyk Bank (Halyk Digital, Процессинг, Кредитные конвейеры, Big Data).

---

## 8. Известные ограничения

1. **Персистентность:** Согласно ТЗ хакатона, все данные хранятся в оперативной памяти Node.js-процесса (In-Memory). При перезапуске сервера состояние инициализируется заново из `/data`.
2. **Аутентификация:** Разграничение ролей сотрудника и HR реализовано на уровне UI-вкладок без корпоративного SSO/OAuth.
3. **Геймификация:** Баллы за рутинные обязательные процессы намеренно не начисляются в соответствии с этическими ограничениями ТЗ.
4. **Язык интерфейса:** Основной интерфейс представлен на русском языке.
