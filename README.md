## 2. Краткое описание — какую проблему решает проект и для кого

### Проблема
В крупной корпоративной среде Halyk Bank сотрудник сталкивается с десятками разрозненных HR-событий (онбординг, курсы, митапы, аттестации, менторинг, комплаенс), приходящих нескоординированными уведомлениями с дедлайнами. Сотрудник не видит прозрачной карьерной траектории и не понимает, какую практическую ценность для его перехода на следующий грейд даёт конкретная активность. В результате обучение проходится формально «для галочки» в день дедлайна, явка на добровольные программы низкая, а бюджет на развитие персонала расходуется неэффективно.

В то же время классические рекомендательные алгоритмы работают по наивному однофакторному правилу («у сотрудника самый низкий балл по навыку X — назначим ему тренинг по X»). Если у Middle Backend-инженера слабее всего развит *Public Speaking (ур. 0)*, но сотрудник трижды пропускал подобные мероприятия, а для перехода на Senior критически необходим *System Design (ур. 2 при требуемых 4)*, наивная система предложит ораторские курсы, демотивируя человека и не решая бизнес-задачи банка.

### Для кого решение
1. **Сотрудники (инженеры, аналитики, менеджеры):**
   - Видят профиль компетенций, разрывы до требований целевой роли/грейда и общую готовность.
   - Получают 1–3 персональные рекомендации развивающих шагов с прозрачным многофакторным объяснением пользы.
   - Могут симулировать карьерный трек («Что если...») и экспортировать официальный ИПР.
   - Мгновенно видят прирост уровня навыков после завершения активности.
2. **HR-специалисты и руководители направлений:**
   - Получают целостный срез по проседающим компетенциям в масштабах банка.
   - Контролируют сотрудников без активного шага развития.
   - Анализируют конверсию завершения программ по форматам (воркшопы, курсы, митапы, менторинг, комплаенс).

## 3. Что реализовано — основные функции и возможности решения

1. **Профиль сотрудника и матрица карьерной траектории:**
   - Отображение текущей должности, текущего грейда, стажа, руководителя и целевой роли.
   - Расчет агрегированной готовности к промоушену в процентах.
   - Таблица дефицита навыков (*Skill Gaps*) с визуальной 5-балльной шкалой и статусом критичности компетенций (множитель x3).
   - **Интерактивные мини-спарклайны (Recharts) и колонка Learning Velocity:** наглядная динамика уровня владения за последние 5 активностей и расчет скорости освоения компетенции (наклон прироста, например `+0.5/act`, `+1.0/act`).
2. **Многофакторный AI-слой рекомендаций (1–3 шага):**
   - Ранжирование программ развития на основе синергии минимум трех обязательных факторов:
     1. **Требования целевого грейда:** соответствие компетенций профилю целевой роли.
     2. **Критичность и разрыв навыка:** приоритет критических разрывов (весовой коэффициент x3).
     3. **Поведенческая история сотрудника:** история завершенных форматов с учетом штрафов за отказы (`declined`), неявки (`no_show`), брошенные курсы (`dropped`) и просрочки (`overdue`).
   - Исключение обязательных комплаенс-курсов, проверка пререквизитов и запрет повторного прохождения завершенных активностей (кроме дискуссионного клуба `EV_036`).
3. **Объяснимость рекомендаций (Explainability):**
   - Синтез обоснования с прозрачным разбором каждого из трех факторов в интерфейсе без галлюцинаций.
4. **Интерактивное обновление прогресса:**
   - Кнопка «Отметить выполненным» на карточке рекомендации или в каталоге моментально увеличивает уровень навыка на заданный `gain` (с ограничением `max_level`), добавляет запись в историю и пересчитывает траекторию.
5. **Карьерный симулятор («Что если...»):**
   - Моделирование перехода на любую специализацию (*Backend, Frontend, DevOps, Data Engineer, System Analyst, QA, Product Manager*) и грейд (*Junior, Middle, Senior, Lead*).
   - Расчет дельты готовности и утверждение новой карьерной цели в один клик.
6. **Радар компетенций (Spider Matrix Chart):**
   - Визуализация профиля 360° на графике Recharts `RadarChart` со сравнением текущего уровня навыков и требований грейда.
7. **Индивидуальный план развития (ИПР):**
   - Генерация официального документа Halyk Bank с листом согласования, экспортом в PDF / печать и копированием в Markdown.
8. **Каталог обучения Halyk Academy:**
   - Полнотекстовый поиск, фильтрация по форматам и навыкам, проверка пререквизитов и возможность прохождения обучающих программ.
9. **HR-дашборд:**
   - Сводные метрики по 200 сотрудникам: средняя готовность, топ проседающих компетенций, конверсия обучающих форматов, список сотрудников без рекомендованного шага с причинами.
10. **Горячая загрузка данных жюри (`POST /api/import`):**
    - Форма и API для мгновенного добавления дополнительных профилей и истории без перезапуска сервиса.

## 4. Как работает решение — кратко опиши основной пользовательский сценарий от входных данных до результата

```
[Входные данные: employees.json, skills.json, events.json, activity_history.csv]
                                │
                                ▼
         [Определение целевой роли и грейда (career_goal или next grade)]
                                │
                                ▼
         [Расчет разрывов: gap = max(0, required_level - current_level)]
                                │
                                ▼
          [Фильтрация событий: non-mandatory, не пройденные, пререквизиты]
                                │
                                ▼
    ┌─────────────────────────────────────────────────────────────────┐
    │ Многофакторный скоринг (Decision Layer):                         │
    │ 1. Skill Score = useful_gain * 30 * (is_critical ? 3.0 : 1.0)   │
    │ 2. History Score = (completed * 6) - (negative * 14)            │
    │    (где negative: declined, no_show, dropped, overdue)          │
    │ 3. Specific Penalty = -25 (если был отказ от данного события)   │
    │ Total Score = Skill Score + History Score + Penalty             │
    └─────────────────────────────────────────────────────────────────┘
                                │
                                ▼
                  [Сортировка -> Топ-3 рекомендации]
                                │
                                ▼
              [Формирование 3-факторного объяснения пользы]
                                │
                                ▼
             [Интерфейс: Профиль + Разрывы + Рекомендации]
                                │
                                ▼
         [Действие пользователя: "Отметить выполненным"]
                                │
                                ▼
       [Мгновенное обновление навыков, пересчет траектории и HR-среза]
```

## 5. Технологии — языки, фреймворки, библиотеки, AI-модели, API и внешние сервисы

- **Языки программирования:** TypeScript, JavaScript, SQL/JSON schema.
- **Frontend:**
  - React 19 (компонентная архитектура, хуки).
  - Vite (сборка и middleware).
  - Tailwind CSS v4 (дизайн-система Halyk Bank).
  - Recharts (интерактивные графики: Sparkline, RadarChart, BarChart).
  - Lucide React (иконографика).
- **Backend:**
  - Node.js & Express.
  - TSX (TypeScript Execution).
  - RESTful API (CRUD сотрудников, карьерные цели, симуляции, завершение мероприятий, HR-аналитика).
- **AI-слой и алгоритмы:**
  - Детерминированный многофакторный Decision-алгоритм на базе взвешенных графов компетенций и поведенческих матриц участия.
  - Синтезатор объяснений рекомендаций на основе контекста целевой роли, критичности разрывов и истории обучаемости.
- **Внешние сервисы и API:**
  - Приложение полностью автономно, не зависит от сторонних платных API и функционирует на 100% локально / офлайн.

## 6. Архитектура проекта — основные компоненты и как они взаимодействуют

```
                    ┌────────────────────────┐
                    │     Web Browser        │
                    │   React 19 Frontend    │
                    └───────────┬────────────┘
                                │ HTTP / JSON
                                ▼
                    ┌────────────────────────┐
                    │   Express HTTP Server  │
                    │      (server.ts)       │
                    └───────────┬────────────┘
                                │
                                ▼
                    ┌────────────────────────┐
                    │ DataStore Engine       │
                    │ (src/server/dataStore) │
                    └─────┬────────────┬─────┘
                          │            │
          ┌───────────────┘            └───────────────┐
          ▼                                            ▼
┌────────────────────────┐                   ┌────────────────────────┐
│ Алгоритм рекомендаций  │                   │ Калькулятор траектории │
│  - Матрица грейдов     │                   │  - Разрывы (Skill Gaps)│
│  - Поведенческий скор  │                   │  - Готовность к грейду │
│  - Explainability      │                   │  - Learning Velocity   │
└────────────────────────┘                   └────────────────────────┘
          │                                            │
          └────────────────┬───────────────────────────┘
                           ▼
              ┌────────────────────────┐
              │ Базовый датасет        │
              │  - employees.json      │
              │  - skills.json         │
              │  - events.json         │
              │  - activity_history.csv│
              └────────────────────────┘
```

- `server.ts` — инициализирует Express-сервер, регистрирует REST API эндпоинты (`/api/employees`, `/api/recommendations`, `/api/hr/overview`, `/api/import`, `/api/roles` и др.) и монтирует Vite.
- `dataStore.ts` — ядро бизнес-логики: хранение в памяти, расчет дефицита навыков, фильтрация пререквизитов, скоринг с весами критичности (x3) и штрафами за отказы, синтез объяснений.
- `SkillGapsTable.tsx` — визуализация матрицы разрывов, 5-точечных спарклайнов динамики и метрики скорости освоения (*Learning Velocity*).
- `CareerSimulatorModal.tsx` — симулятор карьерных переходов («Что если...»).
- `CompetencyRadarModal.tsx` — круговая радар-диаграмма компетенций сотрудника.
- `IndividualDevelopmentPlanModal.tsx` — генератор официального ИПР для печати и согласования.
- `EventsCatalog.tsx` — корпоративный каталог обучения Halyk Academy.
- `HRDashboard.tsx` — аналитический экран для HR с агрегатами по компании.

## 7. Установка и запуск — пошаговая инструкция с необходимыми командами

### Предварительные требования:
- Node.js версии 20+
- npm

### Пошаговые команды:
```bash
# 1. Клонирование репозитория
git clone <URL_РЕПОЗИТОРИЯ>
cd <ПАПКА_РЕПОЗИТОРИЯ>

# 2. Установка зависимостей
npm install

# 3. Запуск сервиса в режиме разработки (Backend API + Frontend на порту 3000)
npm run dev

# 4. Проверка статической типизации и линтинг
npm run lint

# 5. Сборка для production
npm run build

# 6. Запуск production-сервера
npm start
```
После запуска откройте браузер по адресу: `http://localhost:3000`.

## 8. Как проверить решение — пример сценария, который может повторить жюри

### Автоматическая проверка (скрипт верификации всех 5 критериев):
Запустите команду:
```bash
npx tsx src/scripts/verifyAllRequirements.ts
```
Скрипт последовательно проверяет:
1. Размер датасета (200 сотрудников, 14 навыков, 600 записей истории).
2. **Проверочный кейс жюри EMP_001:** проверка, что система рекомендует *System Design*, а не наименьший навык *Public Speaking*, и формирует 3-факторное объяснение.
3. Мгновенный сдвиг навыка и прогресса при выполнении активности.
4. Горячий импорт профилей жюри без перезапуска.
5. Расчет HR-метрик по всей организации.

### Ручной сценарий для жюри:
1. **Проверка кейса с однофакторной ловушкой (`EMP_001` — Алексей Иванов):**
   - Выберите в селекторе сотрудника `EMP_001 (Алексей Иванов, Middle Backend Developer)`.
   - Целевой грейд: `Senior`.
   - В матрице разрывов навык *Public Speaking* равен **0** (минимальный в профиле).
   - В истории зафиксировано 3 отказа/неявки на ораторские тренинги (`EV_006`).
   - Для перехода на Senior критичен навык *System Design* (уровень 2 при требуемых 4).
   - **Результат:** В рекомендациях на 1 месте предлагается воркшоп `EV_003` по System Design, а тренинг по Public Speaking отсекается поведенческими штрафами.
   - В карточке выведено четкое обоснование по 3 факторам (целевой грейд, критический разрыв, история вовлеченности).
2. **Проверка выполнения активности:**
   - На карточке воркшопа `EV_003` нажмите кнопку **«Отметить выполненным»**.
   - Навык *System Design* мгновенно вырастает с 2 до 3, а общая готовность к грейду увеличивается с 77% до 85%.
   - Список рекомендаций мгновенно обновляется.
3. **Проверка карьерного симулятора:**
   - Нажмите **«Карьерный симулятор»** в карточке профиля.
   - Смените целевую роль, например, на *DevOps Engineer (Senior)*.
   - Оцените мгновенный пересчет процента готовности, критических разрывов и нажмите «Утвердить как целевую должность».
4. **Проверка радара компетенций и ИПР:**
   - Откройте «Радар компетенций» для оценки баланса Hard/Soft навыков.
   - Откройте «Экспорт ИПР» и скопируйте Markdown или распечатайте официальный план развития.
5. **Проверка горячей догрузки жюри:**
   - Откройте вкладку «Импорт (Жюри)».
   - Нажмите «Вставить тестовый кейс (EMP_JURY_99)» и «Импортировать в систему».
   - Сотрудник мгновенно появляется в общем селекторе с готовой траекторией.
6. **Проверка экрана HR:**
   - Перейдите на вкладку «HR-Аналитика».
   - Проверьте топ проседающих навыков компании, конверсию обучающих форматов и список сотрудников без следующего шага.

## 9. Данные и интеграции — какие источники данных, API или внешние сервисы используются

- **Структура синтетических данных (каталог `/data`):**
  - `employees.json` — 200 подробных профилей сотрудников Halyk Bank (роль, грейд, стаж, отдел, оценки навыков 0–5, карьерные цели).
  - `skills.json` — 14 ключевых компетенций (Hard/Soft), матрицы требований для 7 ролей и 4 грейдов (Junior, Middle, Senior, Lead).
  - `events.json` — 19 развивающих мероприятий различных форматов с указанием прироста (`gain`), пререквизитов и признака обязательности (`mandatory`).
  - `activity_history.csv` — более 600 записей участия за 24 месяца с детальными статусами (`completed`, `declined`, `no_show`, `dropped`, `overdue`).
- **Интеграции:**
  - Внешние облачные сервисы намеренно не привлекаются для обеспечения 100% отказоустойчивости, высокой скорости отклика (< 50 мс) и соответствия требованиям информационной безопасности корпоративного контура.

## 10. Ограничения — что не реализовано или какие ограничения есть у текущей версии

1. **Хранение состояния в памяти:** В соответствии с регламентом хакатона данные хранятся In-Memory внутри Node.js процесса. При полном перезапуске сервера состояние сбрасывается к исходным файлам `/data`.
2. **Аутентификация:** Роли сотрудника и HR разделены на уровне вкладок веб-интерфейса без подключения к Active Directory / Keycloak банка.
3. **Геймификация:** Согласно этическим ограничениям ТЗ, баллы за рутинные обязательные процессы (заполнение таймшитов) не начисляются, а публичные соревновательные лидерборды исключены во избежание демотивации персонала.
4. **Формат входных данных:** Загрузка новых файлов через API импорта требует соблюдения схемы полей стартового кита.
